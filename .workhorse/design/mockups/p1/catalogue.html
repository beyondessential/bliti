Measurement and fact catalogue

Every reading the device reports today, restated as a measurement or a fact with its traits. Green is a fact (no state, no history); the rest are readings. The last column says what it was before, so nothing is silently dropped.

Trait values are always names, never numbers or flags. Units are spelled out. kind names what the value is, and its vocabulary is open.

Identity

typenamekindtraitswas
facthostnametext—hostname
factboardtext—board headline
factboard-revisiontext—board detail "Revision"
factostext—os headline
factkerneltext—os detail "Kernel"
factuptimeduration—uptime

Uptime is a fact. It changes constantly but has no state and its history says nothing — it only ever climbs, which is why it carried ungraphed. A fact is not a thing that never changes; it is a thing with no state and no history worth keeping. An address is the same.

Network

factnetwork-addressipv4 / ipv6interface{name, route?, overlay?}address headline + detail
readingnetwork-throughputquantity · bytes/secondinterface{name}, directionnetwork-in/network-out + detail
The network group collision dissolves. Addresses and throughput were both grouped as network, which is what forced the per-interface readings to be summed away. They are now separate names, and per-interface throughput is a first-class reading with its own state, error and history.

readingthrottlingbooleanconditionthrottling text summary
readingmemory-usagefraction—memory
readingmemory-bytesquantity · bytespart: usedmemory detail "Used"
factmemory-bytesquantity · bytespart: totalmemory detail "Total"
Throttling becomes one reading per condition, not a sentence. The device currently composes "Undervolted and slowed" as text, which a client cannot act on. Two conditions, each with its own state, is the same information as data. This is the one place a new boolean kind is wanted.
{ "type": "reading", "at": 20308140, "measurement": "throttling",
  "traits": { "condition": "undervoltage" },
  "state": "warn", "kind": "boolean", "value": true }

{ "type": "reading", "at": 20308140, "measurement": "throttling",
  "traits": { "condition": "speed-capped" },
  "state": "ok", "kind": "boolean", "value": false }

Storage

typenamekind · unittraitswas
readingfilesystem-usagefractionfilesystem{mount, device, role?}disk headline + detail
readingfilesystem-bytesquantity · bytesfilesystem{…}, part: freedisk detail " free"
factfilesystem-bytesquantity · bytesfilesystem{…}, part: totaldisk detail " of"
The boot-partition rule moves to the client, and needs a trait to move on. The device currently excludes boot partitions from the headline itself. It now states the role and the client applies the policy — which is the same shape as the address headline moving client-side.
{ "type": "reading", "at": 20308140, "measurement": "filesystem-usage",
  "traits": { "filesystem": { "mount": "/boot/firmware", "device": "mmcblk0p1", "role": "boot" } },
  "state": "ok", "kind": "fraction", "value": 0.9412 }

The device's "one mount per block device, shortest path wins" rule stays on the device: it is deduplication of what to report, not a judgement about what matters.

The board's declared thresholds stay as limits on the sensor that has them, which is the processor core. The note about the figure being the core rather than the case is catalogue knowledge and moves to the client.

Power

typenamekind · unittraitswas
readingpower-sourcetext—power-source
readingbattery-chargefraction—battery headline + detail "Charge"
readingbattery-voltagequantity · volts—battery detail "Voltage"
readingbattery-directiontext—battery detail "Direction"

battery-charge carried both a fraction headline and a "Charge" percentage in its detail, which were the same number twice. One reading now. The caveat about a derived direction is a note about this reading rather than about the measurement type, so it stays on the wire.

What this catalogue decides

Three device-side judgements become client rules. Which address to headline, which filesystem sets the storage headline, and which temperature sensor leads. In each case the device gains a trait stating the fact — route, role, sensor — and stops choosing.
Three details were the same number twice and collapse: battery charge, and the disk fraction that appeared both as the headline and per mount.
One new kind, boolean, so throttling conditions are data rather than an English sentence. Everything else uses text, quantity, fraction, duration, ipv4 and ipv6.
